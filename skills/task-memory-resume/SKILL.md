# 任务状态记忆与恢复

在 **CubeStackInstaller** 仓库(`/home/supperadm/cubestack-installer`)的部署/开发/排障工作中,把**不可从代码或 git 推导**的当前状态持久化,跨会话(下次启动 / 网络中断 / 换终端)恢复。

## 何时保存(触发点)

完成以下任一工作后**强制保存一次**:
- 部署模块成功 / 失败(记录失败原因与恢复路径)
- 脚本修复 / 重构 / 调参完成(记录"改了什么、为什么")
- 集群状态变化(Ceph HEALTH_OK / OSD 数 / 断点位置)
- 会话结束 / 用户说"记住 / 保存 / 下次继续"

**不保存**:代码结构 / git 历史 / CLAUDE.md 已记录的内容、一次性琐碎对话。

## 保存到哪

`~/.claude/projects/-home-supperadm-cubestack-installer/memory/`(会话间持久):
- 每个**任务/主题**一个文件, frontmatter 含 `name`/`description`/`type`(task|session)
- 快照**追加不覆盖**: 同任务多次保存 → `task-name-<YYYYMMDD>.md` 时间戳轮转, 保留最新 N 份
- `MEMORY.md` 索引加一行指针

## 快照格式

```markdown
---
name: <kebab-slug>
description: <一行摘要, 含日期>
metadata:
  type: task
---

# <任务名> — <日期>

## 状态
- 任务: <当前在做什么 / 停在哪一步>
- 断点: <模块名 / 部署阶段 / 状态文件位置与内容摘要>
- 结果: <成功 / 失败 / 部分完成, 失败给根因+恢复路径>
- 环境: <容器名 / 集群地址 / 节点数等, 恢复必需>

## 已完成
- <bullet 列表, 每项 = 改了什么 → 为什么(链接 [[相关记忆]])>

## 下一步
- <待办, 按优先级; 每项含验证方式>

## 风险/教训
- <非显然的坑, 避免下次重复踩>
```

## 如何恢复

1. 会话开始或用户要求"恢复/继续"时: 读 `MEMORY.md` → 取最新相关快照
2. 验证记忆仍有效: 记忆反映**保存时**的真实状态 —— 若与当前现实冲突(文件/集群/状态已变), 以现实为准, 并**更新或删除**该记忆
3. 用快照的"断点 + 下一步"重建执行上下文, 直接续跑
