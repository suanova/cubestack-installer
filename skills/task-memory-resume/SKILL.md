# 任务状态记忆与恢复

**核心原则：记忆文件是跨会话的唯一真相。** 不能等任务全部做完才写 —— 上下文随时可能被压缩/中断；**每完成一个任务或里程碑就更新一次**，下次启动按“断点 + 下一步”直接续跑，不重新分析。

## 记忆位置（固定，不要写错）

- 记忆目录：`/home/ubuntu/.claude/projects/-home-ubuntu-cubestack-installer/memory/`
- 索引：`MEMORY.md`（会话启动时由系统自动加载，但仍要按下节流程读取进行中快照）
- 每个任务/主题一个文件：`<topic>-<YYYYMMDD>.md`
- ⚠ 旧路径 `...-home-supperadm-...` 已失效；一律用上面的 Ubuntu 路径。

## 会话启动：先读记忆（强制）

1. 读 `MEMORY.md`。
2. 对所有带 `[进行中]` 的条目，读对应快照文件。
3. 用一句话向用户确认：`当前进行中: <任务> — 断点 <...>; 下一步 <...>; 已完成: <...>`。
4. 若记忆与当前现实冲突（文件/集群/分支/状态已变），**以现实为准**，立即修正或删除该记忆。
5. 用户说“继续/做到哪了/从记忆恢复”时，直接从最新 `[进行中]` 快照的“下一步”开始执行，不要重读历史对话。

## 何时保存（强制触发点）

以下任一发生后，**立即更新记忆**（不能攒到最后）：

- 任务开始：写目标、计划、当前断点、下一步。
- **每完成一个任务 / 里程碑 / 部署模块 / 修复 / 重构 / 调参 / 诊断结论**：更新状态、已完成、未完成、验证结果。
- 长任务进行中：每完成一个阶段，或准备执行长命令/大范围读取/高风险操作之前，先 checkpoint。
- 任务失败 / 中断 / 发现根因：记录根因、恢复路径、精确命令。
- 会话即将结束、用户说“记住/保存/下次继续”。
- 上下文明显变长（准备压缩/切换会话）时。

**里程碑判定**：一个修复通过验证、一个部署模块结束、一个根因确认、一个方案/文件定稿、或用户确认“可以了” —— 任一发生即保存，不要等“整个任务”结束。

**不保存**：代码结构、git 历史、CLAUDE.md 已记录的内容、一次性的琐碎对话、真实密码/密钥（凭据只写“已配置/路径”，不写值）。

## 更新索引 `MEMORY.md`

每次保存后，更新对应一行（不要重复新增同一任务）：

```markdown
- [进行中] [任务标题](file.md) — 断点/下一步（日期）
- [已完成] [任务标题](file.md) — 结果/验证（日期）
```

规则：
- `[进行中]` 放最上面。
- 已完成的任务保留一行，供回溯；不要把“进行中”写成“已完成”。
- 索引只放一行钩子，细节在快照文件里。

## 红旗（出现即说明该保存了）

- “等全部做完再记” → 上下文可能等不到那时候。
- “我记得住 / 刚才不是做过吗” → 跨会话不保留，写下来。
- “代码/git 里有” → 目标、决策、环境、下一步、未完成项不在代码里。
- “只更新 MEMORY.md 就够了” → 索引只有一行，必须更新任务快照。
- “任务完成了就不用记” → 记录验证结果和后续事项。
- “路径无所谓” → 用固定路径；旧 `supperadm` 路径错误。

## 恢复后的动作

从快照的“未完成 / 下一步”第一项开始；每完成一项就更新该文件与索引。若任务已全部完成，把状态改为“已完成”，并把索引行改为 `[已完成]`。
